# WormholeSystems → Nexum: standalone signature synchronization

## Objective

Synchronize validated signatures for **every system** in the selected WormholeSystems map into corresponding **already-present** Nexum systems, even if the source map contains no connections. Continue the existing guarded topology PUT for source connections and the separately guarded linked-signature alliance-note PATCH. A scan code/type alone never proves a connection, endpoint, destination, bookmark or note.

**Implementation gate:** Public Nexum signature POST is create-only and has neither documented idempotency nor a source-owner marker/uniqueness guarantee. It cannot support unattended retryable imports that also preserve manual rows. Read-only type/coverage work may proceed; automatic standalone writes are blocked until the upstream capability specified below is implemented and approved (or the user explicitly chooses weaker semantics). Principal Reviewer must validate this contract before implementation.

## Authority and dependencies

- [01-wormholesystems-source-and-sync.md](01-wormholesystems-source-and-sync.md) governs one configured source/target map, fully fetched map/member snapshot, explicit EVE system identity, opaque source IDs, connection references and source activation. The adapter retains source metadata and normalizes resource `id`, code `signature_id`, scanner system and optional `map_connection_id`. Its normalized signature `status: "unknown"` is not evidence that a scan is inactive.
- [02-wormholesystems-nexum-reconciliation.md](02-wormholesystems-nexum-reconciliation.md) governs topology ownership/manual-data preservation, linked-note identity and note safety, selected-map legacy writer suppression, and per-map decision boundary. [03-wormholesystems-runtime-freshness-policy.md](03-wormholesystems-runtime-freshness-policy.md) governs global durable initial 60,000 ms policy, source/map/signature-cache decision-time freshness, revision fencing and fail-closed invalid policy. Keep all established behavior.
- Current boundaries: `src/wormholesystems.ts` stages an atomic complete source snapshot, then attempts guarded topology and separate notes; `src/nexum.ts` writes topology via custom PUT and notes via target row UUID PATCH; `src/nexum-client.ts` lacks POST; `src/nexum-store.ts` caches whole per-system signature arrays, not standalone inserted rows. Galaxy's SQLite transaction cannot encompass a Nexum network write. The supported one-process Galaxy map lock cannot serialize independent Nexum UI/other writers.
- Nexum public API research: `GET/POST/PATCH/DELETE /api/v1/maps/:mapId/systems/:systemId/signatures`; POST returns 201 for creation, not upsert, with no documented idempotency, uniqueness, or generic provenance. Writable POST fields: `sigId`, `sigType`, `name`, `notes`, `whType`, `whLeadsTo`, `ghostType`, `massStatus`, `timeStatus`; **no writable size**. GET distinguishes scan `sigId` and row `id`; PATCH URL `:sigId` actually requires the row UUID. `scoutConnectionId` (PATCH only) serves Thera/Turnur, not generic source ownership. Extra JSON fields are ignored. Map content write authorization / API key `write` scope and target system membership are required; API does not create target systems/topology. Create/update emits `sig.changed` and can cross-map-sync. The existing custom `/wormholesystems/topology` is separate and remains authoritative for current link writes; do not replace it. No undocumented enum validation/semantics are assumed.
- User observations: current complete source snapshot has 2 systems, 12 signatures (all on EVE system `31000375`), 0 connections and 12 normalized unknown statuses. User identifies `RZQ-108` and `VGC-572` as wormholes with populated source type. Preview currently exposes codes but not types. Current target `Vermis` cache has only 1 system, so selected-map target coverage is incomplete. Currently selected Nexum credential has `read` + `live_events`; do not assume content write permission. Do not perform live calls or read credentials to verify this design.

## Scope and dependency order

1. **Validated source field/read-only preview.** Extract bounded classification/type for each source signature from an approved schema/deployed fixture. Determine exact source field paths, values and compatibility with Nexum `sigType`/`whType` before treating them as write authority; preserve raw metadata as opaque. Add versioned/validated canonical evidence or a compatible extension, and require a fresh validated source sync when an older persisted snapshot lacks type evidence. The user's two named wormhole examples require fixture assertions, not invented JSON fields or generic type mapping. Extend local-only preview for every source signature to show scan code plus validated classification/type or a precise unavailable/unverified reason, including unconnected records.
2. **Nexum atomic source-owned signature capability, before any automatic write.** Add a server-side integration interface (or obtain a verified upstream equivalent) that atomically binds `(target map, configured source namespace/map, opaque source signature resource ID)` to one target row/system/code; enforces unique owner key and row/code conflicts in Nexum persistence; retries after a lost response return the **same** proven row rather than inserting; and never claims manual/unowned rows. Uniqueness/conflict detection for `(map, system, scan code)` must cover **all** Nexum creation pathways (manual, public POST, topology, integration) transactionally using the destination's documented code-equivalence rule; a mere preflight GET does not prevent a race. Preexisting duplicate codes must be flagged/blocked, not deleted to force a uniqueness migration. It must reject key reuse with changed scanner system/code, enforce map membership and map-bound integration/content-write authorization, and return row UUID + binding/ownership proof. Updates to permitted source-owned fields require server-side compare against last applied values or equivalent conditional version check; a manual edit must conflict instead of being overwritten. Coordinate ownership with any signatures created by the existing topology PUT, without weakening its topology ownership guards. Preserve binding/idempotency across Nexum restart and `sig.changed`/cross-map side effects. Do **not** emulate this using extra public POST fields, `notes`, `scoutConnectionId`, or GET-by-code after a lost response.
3. **Galaxy journal and reconciliation, conditional on step 2.** Add an additive durable per-source-row binding/attempt journal independent of whole-array target cache and existing source-run journal. Run per-system plans against the validated complete source snapshot and the atomic Nexum capability. Keep topology/notes running under their existing gates. Without step 2, implement only read-only field/coverage diagnostics with a visible standalone-write blocker; never fall back to plain POST.
4. **Operator surface.** Keep `wormholesystems_sync_map`, `wormholesystems_map_sync_status` and `wormholesystems_preview_map_sync` for the selected canonical map. Add bounded `standalone_signatures` preview/outcomes with source total, typed/blocked/confirmed/unknown counts, per-system coverage, collision/missing-target/write-scope blockers, and explicit partial/full completion. Test/enrollment/source enablement do not grant Nexum write permission. Any additional explicit write activation required by the Nexum capability is operator-controlled; do not infer authority from successful source fetching. Never expose raw upstream records, notes, keys or unsanitized error bodies.

## Required behavior and interfaces

- Iterate every validated source member detail, regardless of connection count or `status: "unknown"`. One source signature resource ID yields at most one target row. Stable source key = target canonical map + configured source namespace/selected upstream map + opaque source signature `id`; persist source member ID, scanner EVE ID and exact scan code as immutable binding checks, **not** replacement identity. Distinct source rows with the same scan code in one scanner system are conflicts. Select target by exactly one EVE solar-system ID match among systems **already members** of the selected Nexum map; no alias/name/position guessing, source-ID-to-target-ID substitution, or target system creation.
- Minimum write allowlist: validated `signature_id` scan code → Nexum `sigId`; proven category → `sigType`; proven wormhole type → `whType` only if source field/value and destination representation are verified. Separate wormhole classification from specific type. A source `wormhole_id` is an ID, `leads_to` is not an exact destination, connection `type`/`ship_size` does not classify an unlinked scan, and normalized `unknown` is not an inactive signal. Omit absent optional type; block a row when the required Nexum classification is not proven. Do not write `name`, `notes`, `whLeadsTo`, `ghostType`, `massStatus`, `timeStatus`, `scoutConnectionId`, arbitrary fields or size in this minimum import. Expansion requires separate verified semantics and ownership rules. Do not claim specific field/value for `RZQ-108`/`VGC-572` without validated fixture evidence.
- A target code match is **not** ownership. Existing manual/unowned rows (even those with the two named codes), ambiguous same-code rows and unexpected code changes are conflicts, never adopted/overwritten/deleted. Only Nexum-proven ownership plus corroborating Galaxy binding permits an update; refuse updates on manually edited source-owned fields. On source disappearance, move, code change, target row disappearance/reassignment or configuration switch, retain binding/history, report drift and require explicit resolution; no auto-delete, automatic recreate, unbind/rebind, clearing notes or transfer of ownership. Existing note PATCH rules alone govern linked alliance text; preserve other manual data/custom labels.
- The source fetch remains map-wide/atomic, but independently safe **per-system partial** signature progress is allowed when some target members are missing/ambiguous. Missing/ambiguous source system → target identity blocks that member without choosing a candidate; mark full selected-map signature sync **incomplete** (including current 2-source/1-target state). Other uniquely resolved members may progress only if their target map and per-system signature cache are fresh/healthy and all source, policy, credential and ownership checks pass. Do not promote global `eligible_for_matching`/`eligible_for_writes` because one standalone member is eligible; report independent per-system eligibility and coverage. Keep existing topology's complete-map/edge/freshness guard unchanged.
- Continue guarded topology PUT when source connections exist; never infer links/endpoints from unconnected signatures. If topology creates a row with the same code/source key, the new capability must prove compatible ownership or reject conflict, not double-create/adopt. Refresh/validate affected map/signature caches after topology before standalone planning. Topology failure does not itself suppress independently eligible standalone scans; standalone failure does not cancel separately eligible topology or linked-note work. A linked signature can import a scan row on its scanner side, but note PATCH still requires an exact validated source edge, directional target row UUID and current safe note state; an unlinked or newly created row alone cannot authorize `.FROM-TO ...` or other alliance text. Continue selected-map legacy note suppression and unrelated-map behavior.

## Invariants: persistence, concurrency, recovery

- Journal under `(target map, source namespace/map, source signature ID)` with source member/EVE ID, scan code, validated field digest, intended target system, server binding/row UUID/version when proven, source/config/policy revisions, attempt ID/times and explicit `planned`, `in_flight_or_unknown`, `confirmed`, `blocked/conflict`, `reconcile_required` states. Enforce local unique source-key/target-row bindings; server enforces these atomically too. Existing cached/manual rows cannot be backfilled as owned. Corrupt/contradictory binding state fails closed. Preserve historic bindings on source loss without authorizing writes under changed identity; never store keys/raw notes.
- Commit a durable intent **before** each network mutation. Record confirmed/blocked/failed/unknown/not-attempted item outcomes and run summary after response. Serialize map decisions against source snapshot/config/policy changes, topology, standalone and notes within the Galaxy process; at each operation recheck source identity/revision, map membership, validated fields, policy revision, 03 decision-time source/map/affected resource freshness, writer authorization and ownership. No SQLite transaction spans a network call. External concurrency and indeterminate delivery are solved by the server's atomic source-key idempotency/conditional update, **not** Galaxy locking or a pre-POST GET.
- After timeout, process crash or lost acknowledgement, `in_flight_or_unknown` is not permission to send public POST again or adopt a matching target row. Reconcile/retry **only** through the upstream source-key endpoint, verifying returned row UUID, system, code and ownership; 409/unexpected row/stale cache remains blocked. Bounded retry/backoff; 401/403 needs operator remediation and must not silently switch to another unverified key. Rehydrate target resources after successful mutation/event before claiming fresh whole-array cache (do not append a guessed row). Partial cross-service writes never report all-systems success. `read` + `live_events` selected key shows a no-write blocker without probing with a live write. Public key scope introspection is unavailable: operator-declared/bound writer plus actual server authorization is required; source enablement alone does not qualify.
- Retain 03's inclusive `now - timestamp <= max_staleness_ms`, reject future/missing stamps, changed policy/source/config revision and invalid persisted policy. Recheck after each long-running member operation; no stale preview authorizes a later write. Operator Cloudflare Access path remains the chosen operator boundary; do not invent new Galaxy application auth or claim local MCP port is secure.

## Validation and acceptance

Principal Reviewer validates the architecture and the Nexum extension's guarantees before implementation. Mocked adapter/transport and database-backed Nexum integration tests (where DB available) cover:

1. Zero connections, multiple source members, 12 signatures: preview shows every row with code and validated type/classification or precise blocker, including `RZQ-108` and `VGC-572`; no inferred endpoint, topology, note or destination. With eligible target membership and authorized writer, standalone scans import to **each** member without links. Current 2-source/1-target and read/events-only fixture reports incomplete coverage and no unauthorized write.
2. Recorded links plus standalone scans: existing topology PUT persists and guarded linked notes remain; topology-created row does not double-create or get manually adopted. Failure in one branch does not falsely report another branch failed/succeeded; unrelated maps retain legacy notes.
3. Existing manual code collision, multiple target matches, manually edited bound row, source code/owner change, source disappearance and externally deleted/reassigned row: explicit conflicts; no adoption, overwrite, rebind or auto-delete. Refresh after `sig.changed` and cross-map effects; verify cache timestamps and ownership.
4. Concurrent UI/public POST/topology writer, preexisting duplicate codes, timeout after Nexum commit, duplicate source-key request, restart between intent and acknowledgement, failure to save local confirmed outcome, server 409 and retried partial runs: one proven row, explicit unknown/conflict where appropriate, no duplicate or guessed adoption. Do not use unprotected public POST as a mock of the required atomic capability.
5. Missing/ambiguous target system, stale/missing per-system signature cache, future/stale source or target map, invalid persisted policy, changed policy revision at final check, exact 60,000 ms boundary, disabled source, no content-write credential or 403: fail closed for affected writes, permit only independently eligible per-system progress and mark full sync incomplete. Unit tests use mock transport/fixtures, never live calls or credential reads; build/tests `npm run build` and `npx vitest run`, report DB-backed/deployment checks unavailable when so.

## Out of scope

Target system creation, endpoints from type/code, generic two-way sync, source writes, polling/webhooks, changing topology ownership, relaxing 03, unsupported fields, automatic signature deletion or owner transfer. Public POST/PATCH must not be presented as a guaranteed upsert.

## Open issue — blocking upstream guarantee and deployment verification

Before production standalone writes, obtain an implemented/reviewed Nexum source-key atomic ownership/idempotency/conditional-update interface interoperable with topology-created rows **or ask the user to approve weaker best-effort/manual-resolution semantics** (which can duplicate scans or strand ambiguous outcomes). This document does **not** choose weaker semantics on the user's behalf. Plain create-only POST plus local journal cannot deterministically recover a lost acknowledgement or prevent a concurrent manual insertion between GET and POST. Until resolved, standalone writes remain disabled with an explicit blocker; read-only type preview and existing topology/notes remain independently usable. Actual deployed WormholeSystems type paths/values, Nexum accepted `sigType`/`whType` semantics and target content-write authorization also require separate verification without live probing during design.
