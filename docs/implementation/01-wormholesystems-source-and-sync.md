# WormholeSystems → Galaxy: bounded source integration

## Objective

Make WormholeSystems-derived chain/bookmark authority available to Galaxy for **one explicitly enabled Nexum map**, then reconcile that map's topology and alliance-formatted signature notes in Nexum without assuming an undocumented upstream deployment contract. This source contract feeds [02-wormholesystems-nexum-reconciliation.md](02-wormholesystems-nexum-reconciliation.md) for linked-direction notes and [04-wormholesystems-topology-and-signatures-apply.md](04-wormholesystems-topology-and-signatures-apply.md) for transactional system/signature/connection apply. Unconnected signatures need no source link or preexisting target system; writes require unit 04 ownership, idempotency and freshness gates.

The source map member `id` and canonical `solarsystem_id` are distinct; `position` is the map canvas position, and `home_solarsystem_id` identifies home. A successful full map/member snapshot establishes recorded connection presence; the completed snapshot `fetchedAt` governs freshness, with no per-row timestamp required. System `status` is visual intel, not topology presence or liveness. Alliance annotations require the validated settings vocabulary.

## Required behavior and interfaces

Route parameters are source identities, not EVE or Nexum identities. Select one map from the authorized `GET /api/maps` result by its configured upstream identity; for `GET /api/maps/{map}`, send that selected map's returned `id` as `{map}` (e.g. string `"2"`), and require the returned map detail `id` to equal the selected list/configured map `id`. The cited upstream [`Map` model](https://github.com/WormholeSystems/WormholeSystems/blob/b5bda803b99bd0e7d01fabb2aa80c96595cdfc67/app/Models/Map.php) uses [`HasSlug`](https://github.com/WormholeSystems/WormholeSystems/blob/b5bda803b99bd0e7d01fabb2aa80c96595cdfc67/app/Traits/HasSlug.php), whose route binding also accepts a slug ending in the map ID; this contract chooses the map `id`, **not** the `slug`, as the route value. For each `GET /api/map-solarsystems/{mapSolarsystem}`, send the selected map's `map_solarsystems` member row's opaque `id` as `{mapSolarsystem}`, **never** its EVE `solarsystem_id`; require the detail's `id`, `map_id` and `solarsystem_id` to agree respectively with that member's `id`, selected map's `id` and that member's `solarsystem_id`. Reject any mismatched detail rather than attaching it to the requested member. These source-commit route-binding facts do not replace separate deployed route/path compatibility verification before enablement.

The source adapter's internal API yields `{ sourceIdentity, revisionOrDigest, fetchedAt, observedAt, systems, connections, signatures, authorityMetadata, sourceMetadata }`. Only validated `solarsystem_id`/`home_solarsystem_id` values identify EVE systems; map `id`, map-solarsystem `id`, connection `id`, signature resource `id` and wormhole `id` occupy separate opaque source-ID namespaces and never become Nexum IDs. Connect `from_map_solarsystem_id`/`to_map_solarsystem_id` to selected-map member `id`, then obtain canonical EVE IDs from those members' `solarsystem_id`; use signature `map_solarsystem_id` the same way. Directional identity is `(scannerEveSystemId, signatureCode, sourceSignatureId)` with `signatureCode` from `signature_id` and `sourceSignatureId` from signature resource `id`; connection identity includes source connection `id` so concurrent links remain distinct. Require `id` on both full per-system signature objects and slim signatures nested under connections; use each only as its opaque source signature-resource identity for directional identity/deduplication and cross-reference checks, never as `signature_id` (the code), EVE system ID or Nexum ID. Check `map_connection_id` and nested connection/signature references against this map's IDs when supplied, without inventing an absent reverse link or requiring full-resource-only fields on a slim signature. Map field names exactly. Validate source aliases against the home/decimal scheme and settings-provided alliance vocabulary; use source system status only as an annotation, never as topology liveness. Do not infer freshness from `signatures_pasted_at` or per-row timestamps, and do not infer destination EVE ID from wormhole `leads_to`. Unsupported or ambiguous note evidence blocks only the affected directional note; an unmapped/unavailable signature category uses unit 04's `unknown`/empty-WH diagnostic fallback without dropping the source row or blocking a complete data sync. Malformed/contradictory identity blocks the write. If note evidence is insufficient, report a match as conflicted/ineligible, not guessed.

### F-1: minimum source-map evidence for topology and alliance annotations

This mapping supplies the validated source fields used by Galaxy's conditional Nexum topology and alliance-note reconciliation. The pinned [map/member/connection/signature resources](https://github.com/WormholeSystems/WormholeSystems/tree/b5bda803b99bd0e7d01fabb2aa80c96595cdfc67/app/Http/Resources), [source enums](https://github.com/WormholeSystems/WormholeSystems/tree/b5bda803b99bd0e7d01fabb2aa80c96595cdfc67/app/Enums) and the [published bookmark-format guide](https://legacy.wormhole.systems/documentation/bookmarking/customizing-the-format) establish field presence and the *source application's* meanings; this repository has not verified that the alliance deployment returns the same values or that its configured template equals the guide's default. Validate the deployed payload before relying on it. Do not substitute source row IDs for EVE or Nexum IDs.

Map `map_connections[].id` is a distinct edge key; resolve `from_map_solarsystem_id` and `to_map_solarsystem_id` through **that map's** member keys to EVE IDs. Keep parallel edges distinct. A connection with either endpoint unresolved is blocked individually, not guessed. |

An unsupported source-present connection type blocks the **entire** sync write before HTTP: retain the source row for diagnostics, but never omit it from a purportedly complete deletion-authorizing projection, advance the checkpoint or authorize deletions from that projection. Two endpoints alone do not make an unsupported source edge safe to project. |

Map `home_solarsystem_id` is an EVE ID; mark home only on its matching member, and flag absent/nonmember/ambiguous home instead of inventing one. The guide's numeric/alphabetic schemes describe suggestions, not proof of this map's stored aliases. |

For the guide's `{sig}` token, use letters only **only when a valid stored scan code permits it**; absent, unlinked or ambiguous codes block that directional note, not the unrelated topology. |

Presence in the complete `map_connections` list proves an edge is **currently recorded on this map**, not physically traversable; the source does not expose a separate per-edge `active` flag. Do not manufacture one or require one for topology reconciliation. An `expired` lifetime remains a recorded annotation, not proof that the source has already deleted the edge.

The source map exposes `bookmark_format_wormhole`, `bookmark_format_kspace`, `bookmark_format_return`, `bookmark_alias_scheme` and `bookmark_ignored_alias`; the guide's defaults are `{alias} {sig} {class}` into J-space, `{alias} {class} {sig} {name} {region}` into K-space, and a `*` return convention ([cheat sheet](https://legacy.wormhole.systems/documentation/bookmarking/cheat-sheet)). **These are not proof of the alliance's actual template or the exact Galaxy authority records.** Use the selected map's validated settings and confirmed authority to render, otherwise return per-direction missing-template/alias/signature/destination/path/token blockers; do not write a fabricated note. Source snapshot `fetchedAt` is stamped after all selected-map/member GETs complete and stored only after validation; a recent *complete* fetch plus its digest and configured maximum age is source retrieval evidence. Do not require per-system/signature/connection `observed_at` fields absent from the cited resource contracts. Multi-GET retrieval is not an atomic upstream transaction: identity/cross-reference contradictions fail validation, and `fetchedAt` proves when collection completed, not the age or physical truth of each scanner observation. Retain Nexum's separate hydration/signature freshness and map-scoped controls. Topology updates/deletes remain limited to records proven created and still owned by this source/map integration; a missing row in a failed/incomplete snapshot, manually managed records and uncertain provenance are not deletion authority. Unit 04 governs safe deletion of absent unchanged owned rows only from a later complete eligible snapshot. Never automatically clear notes because a source record disappears. No per-change approver workflow or new application-auth layer is introduced.

Sync is serialized per enabled canonical map and shares the per-map mutation/decision boundary with unit 02's note and unit 04's data writes: snapshot replacement, authority-mode changes, and final checks/writes cannot interleave in this process. A disabled or different map must never fetch, stage, or write under this integration. On fetch/parse/auth/rate-limit failure, retain last good snapshot for labeled read-only diagnostics, mark it **ineligible for new writes**, and do not silently substitute old chain plans. A newer successfully validated snapshot supersedes the old one atomically; reject older revisions/observation times when order is verifiable, otherwise require a deterministic digest and record that ordering is unknown. Do not delete Nexum data on failed/stale/incomplete source retrieval; unit 04 alone permits safe removal of unchanged source-owned rows missing from a newly accepted complete snapshot.

Matching freshness is governed by the operator-approved initial 60,000 ms runtime policy in [03-wormholesystems-runtime-freshness-policy.md](03-wormholesystems-runtime-freshness-policy.md), not `GALAXY_WORMSYSTEMS_MAX_STALENESS_MS`. The bound applies at decision time to source fetch completion for both units and to Nexum map/signature caches required for note matching, not for initial data creation; a missing or invalid **post-initialization** persisted policy fails closed. Changing the policy does not retroactively turn a legacy stored ineligible snapshot into an eligible one: a new successful sync is required for that snapshot.

Bound requests: explicit connect/response timeout and abort/await on shutdown; one in-flight sync per target map, at most 100 serial system-detail GETs spaced one second apart, bounded response size, and bounded retries; exponential backoff with jitter for transient errors and honor `Retry-After` for 429/503 (seconds and HTTP date). 401/403 require operator correction, not immediate retry. Scheduled selected-map sync is governed by unit 06; do not add webhook listeners, subscriptions, or upstream mutations. Ordinary Nexum/chain reads continue to use local data only.

The operator-approved source origin is an exact HTTPS origin (scheme, host and explicit/default port), separate from a configurable verified API path prefix: reject origin credentials, query, fragment, non-HTTPS, ambiguous/invalid host or port; constrain the path prefix to the approved deployment route, not a caller-provided full URL. Compose inspected resource paths with that prefix after deployed route-binding verification; do not follow URLs from upstream responses. Before attaching bearer credentials enforce exact origin equality. Reject redirects (`redirect: "error"`) for every credential-bearing request including validation and retry; no redirect, fallback endpoint or diagnostic follow-up may forward credentials to a different origin. Fail closed on redirect and sanitize error bodies. Fake transport tests cover origin/path validation, exact-origin credentials, redirects and zero credential-bearing requests to a different origin. Production origin, path and deployed response mapping remain configurable rather than guessed.
