# WormholeSystems → Galaxy: bounded source integration

## Objective

Make WormholeSystems-derived chain/bookmark authority available to Galaxy for **one explicitly enabled Nexum map**, without assuming an undocumented upstream deployment contract or changing Nexum topology. This is the prerequisite for [02-wormholesystems-nexum-reconciliation.md](02-wormholesystems-nexum-reconciliation.md).

The user supplied authoritative record IDs and requested retrieval from Galaxy DB/API, not reconstruction. The configured local `~/.eve-sde/galaxy-state.db` is absent and no Galaxy API/resource connection is available in this workspace: the records' contents, supersession and exact bookmark specification remain **unretrieved**. Do not invent record contents or interpret legacy chain labels as new authority. Retrieve the exact user-supplied IDs when access becomes available.

No new identity scheme or app authorization is in scope.

Registration and testing alone never enable it. Reuse `SecretStore`; do not expose secrets in metadata or MCP output. Update `docs/nexum.md` and `docs/container-deployment.md` for credential enrollment, encrypted storage and `galaxy-secret.key` backup/restore consequences.

Include source identity, stable content digest, retrieval/observation timestamp, scope, EVE solar-system IDs, directional signature and connection identity, source status/freshness where explicitly recognized, and **actual authority fields only after the requested records are retrieved**. The adapter v1 candidate schema requires `map_solarsystems` rows with `id` and `solar_system_id`, selected detail with `signatures`, `connections`, and `audit` arrays, signature `id`/`signature_code`, and map connection `id`/`source_map_solarsystem_id`/`target_map_solarsystem_id` with optional explicit signature references and status/freshness fields. It retains map settings, aliases and other response fields as opaque JSON but does not interpret unknown alias/status semantics. This is a strict candidate contract, not a deployment assertion. Validate scoped map access, map-detail identity, and selected map-solar-system identity; bound fan-out to 100 serial GETs with pacing and a bounded full snapshot size. Reject unsupported/contradictory required shapes and keep sanitized path-only diagnostics. Do not assume source IDs constitute Nexum IDs.

Sync returns revision/digest, counts, freshness, skips and whether Nexum writes were attempted (always **no**); preview makes zero upstream requests and reports identity matches, unmatched rows and conflicts from the local source snapshot plus Nexum cache. Do **not** add app authentication, identity middleware, gateway changes or other new protections contrary to the user's decision; document that the Cloudflare deployment boundary is user-confirmed but cannot be tested from this repo, and never label a local unauthenticated MCP port operator-secure. ## Required behavior and interfaces

The source adapter's internal API yields `{ sourceIdentity, revisionOrDigest, fetchedAt, observedAt, systems, connections, signatures, authorityMetadata, sourceMetadata }`. IDs are opaque strings except explicitly validated EVE solar-system IDs; keep raw source and Nexum object IDs distinct. Directional identity is `(scannerEveSystemId, signatureCode, sourceSignatureId)` and connection identity must distinguish concurrent links. Candidate fields are mapped only by exact names and documented values; omitted, nullable or unrecognized source status/freshness remains `unknown`/`null`, with original source data retained as opaque metadata. If status or freshness evidence is insufficient, report an identity match as conflicted/ineligible; do not fill gaps by guessing.

Sync is serialized per enabled canonical map and shares unit 02's per-map mutation/decision boundary: snapshot replacement, authority-mode changes, and the final check/write stage of either legacy or new note reconciliation cannot interleave in this process. A disabled or different map must never fetch, stage, or write under this integration. On fetch/parse/auth/rate-limit failure, retain last good snapshot for labeled read-only diagnostics, mark it **ineligible for new writes**, and do not silently substitute old chain plans. A newer successfully validated snapshot supersedes the old one atomically; reject older revisions/observation times when order is verifiable, otherwise require a deterministic digest and record that ordering is unknown. Do not delete data in Nexum on source disappearance.

Matching freshness is governed by the explicitly configured positive safe-integer `GALAXY_WORMSYSTEMS_MAX_STALENESS_MS` value. There is no default: an unset or invalid value blocks snapshot matching eligibility and keeps any candidate identity match incomplete/conflicted. The threshold applies to source snapshot age, Nexum map hydration age and signature-resource cache age; changing it does not retroactively validate an old snapshot that was staged without a configured threshold, so synchronize again after configuration.

Bound requests: explicit connect/response timeout and abort/await on shutdown; one in-flight sync per target map, at most 100 serial system-detail GETs with pacing, bounded response size, and bounded retries; exponential backoff with jitter for transient errors and honor `Retry-After` for 429/503 (seconds and HTTP date). 401/403 require operator correction, not immediate retry. Do not implement scheduled polling, webhook listeners, subscriptions, or upstream mutations. Ordinary Nexum/chain reads continue to use local data only.

The operator-approved source origin is an exact HTTPS origin (scheme, host and explicit/default port), separate from a configurable verified API path prefix: reject origin credentials, query, fragment, non-HTTPS, ambiguous/invalid host or port; constrain the path prefix to the approved deployment route, not a caller-provided full URL. Compose inspected resource paths with that prefix after deployed route-binding verification; do not follow URLs from upstream responses. Before attaching bearer credentials enforce exact origin equality. Reject redirects (`redirect: "error"`) for every credential-bearing request including validation and retry; no redirect, fallback endpoint or diagnostic follow-up may forward credentials to a different origin. Fail closed on redirect and sanitize error bodies. Fake transport tests cover origin/path validation, exact-origin credentials, redirects and zero credential-bearing requests to a different origin. Production origin, path and deployed response mapping remain configurable rather than guessed.
