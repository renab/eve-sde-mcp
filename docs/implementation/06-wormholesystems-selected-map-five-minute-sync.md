# WormholeSystems selected-map automatic five-minute sync

## Objective and authority

Automatically fetch and reconcile the **one configured selected map** every five minutes, without an operator calling `wormholesystems_sync_map`. The user's standing five-minute requirement supersedes the on-demand-only/no-polling language in units 01, 02, 04 and 05. Manual sync remains available. This unit changes *when* the existing data sync runs, not its source/target protocol, projection, classification, signature-name behavior, or linked-note policy.

Authority: `src/wormholesystems.ts` `syncMap` is the validated manual entry; units [01](01-wormholesystems-source-and-sync.md), [03](03-wormholesystems-runtime-freshness-policy.md), [04](04-wormholesystems-topology-and-signatures-apply.md), and [05](05-source-signature-names-and-reconciliation-outcomes.md) govern complete fresh source-v3 fetching, Nexum request-v3 projection, binding, frozen requests/retries, checkpoint interpretation, and independent note gates. `src/map-decision-boundary.ts` is **process-local**. `src/keep-warm.ts` and `src/http.ts` supply the lifecycle timer precedent; `src/wormholesystems-client.ts` honors bounded Retry-After. No WHS timer currently exists. The topology endpoint's map transaction/checkpoint is authoritative for mutation and replay, not an upstream scheduler lock.

## Scope and dependencies

Add a service-lifecycle scheduler that dispatches the existing `syncMap(configuredCanonicalMapId)` path; do not duplicate fetch, validation, SDE enrichment, projection, PUT, or retry logic. Start after service initialization and stop on shutdown, including teardown on startup failure; work for HTTP/MCP deployment without needing an operator session. Decide eligibility from **current persisted configuration each tick**, not an enrollment/startup snapshot: source enabled, successful current source connection/schema test, selected canonical/upstream map, current bound writer and v3 endpoint confirmation, and all existing per-send guards. Missing/invalid policy, identity, source credentials, writer binding, target authorization or deployment confirmation blocks writes rather than falling back to a different map/key. A configured-but-unbound map must not generate write-authorizing fetches through a background path. Disable/removal/reconfiguration/credential replacement immediately suppress subsequent starts, invalidate queued work and retain the current service's final-send/retry revision checks; stopping work must abort/await bounded in-flight requests, not rewrite or discard indeterminate outcomes.

Cadence is **fixed-rate**: monotonic five-minute slot boundaries established on scheduler start, one opportunity per slot, not five minutes after the previous completion. No immediate startup write or replay of downtime slots; first opportunity is at the first boundary five minutes after startup. A slow/blocked attempt skips occupied slots; never queue catch-up attempts, create overlapping scheduled runs, or accumulate timer callbacks. Dispatch uses latest config each slot; manual invocations may occur between slots and do not shift the clock. An eligible manual run occupying a slot counts as the in-progress sync (skip this scheduled slot); deduplicate local concurrent manual/scheduled entry at `syncMap` rather than interpreting two callers as independent writes. A manual request should retain its established result contract. Scheduler failures must never crash the service; normal fixed-rate opportunities resume after bounded Retry-After/backoff *inside* the existing sync, with no second unbounded retry loop and no burst on recovery. On shutdown stop timer first, prevent new dispatch, then await/abort active sync using existing service shutdown limits.

## Cross-replica correctness and fencing

**Verified deployment boundary for the first release:** homelab `platform/galaxy/statefulset.yaml` specifies StatefulSet `replicas: 1` with RollingUpdate/OrderedReady (one live `galaxy-0`); `platform/galaxy/configmap.yaml` sets `GALAXY_STATE_DB=/home/node/.eve-sde/galaxy-state.db`, and the ReadWriteOnce PVC mounts at `/home/node/.eve-sde`. Implement one in-process scheduler for this one worker, preserving the existing single-process `syncMap` manual/scheduled serialization. Assert and operationally verify exactly one running Galaxy scheduler/writer before activation and during rollout; ReadWriteOnce is **not** a distributed mutex or scale-out authorization. Do not add an unused distributed lease service to this release. Scaling beyond one active scheduler/writer is blocked until a shared lease/leader-election design, including fencing and coordination of manual callers, is implemented and verified.

The map decision boundary and `syncs` promise map are not distributed locks; do not claim exactly-once across replicas. Future deployment with more than one active worker must use a shared durable per-selected-map coordinator protecting *both scheduled and manual* `syncMap` operations across replicas (not just the timer), acquired before source fetch and held through frozen-write outcome recording. A per-process flag, pod-local SQLite file, and unshared advisory lock are insufficient. For a multi-replica implementation, select and verify a real common lock store (e.g. an available shared PostgreSQL session advisory lock with dedicated, monitored connection); never assume Galaxy SQLite files on independent pods constitute a shared lock. Fail closed (skip scheduled, reject or report busy for manual) when the coordinator is unavailable, its storage is not demonstrably shared, or ownership is lost; cancel unsent requests and mark any sent/unacknowledged PUT indeterminate. Do not open a SQLite transaction across HTTP. Release in `finally` only if still owner.

**Fencing:** a renewable expiring lease by itself cannot fence an in-flight HTTP PUT after expiry. Either hold a confirmed non-expiring shared advisory lock for the entire operation and treat lost connection as indeterminate, or enforce monotonically increasing fencing tokens at the write recipient before commit; do not ship a lease-based multi-replica mode without recipient-side enforcement. This unit does **not** authorize inventing a Nexum v4 protocol. With advisory-lock loss, Nexum's own map lock and `(map, source, fetchedAt, digest)` checkpoint still reject stale/duplicate writes, but cannot promise exact-once source fetch or eliminate a previously sent indeterminate write: document this limit, recheck frozen request/freshness and checkpoint outcome before any retry, never regenerate `fetchedAt` for a retry. If a verified common lock cannot be provided without a new protocol, deploy a single active scheduler/writer and make replica count/topology a rollout gate; do not silently enable a timer in each pod. Manual and scheduled requests use the same service's map-decision boundary for config/policy/write decisions; no distributed lock should bypass its existing guards.

## Invariants, observability and validation

- Preserve complete validated fresh source-v3 evidence, source/target exact identity, 60-second default persisted freshness (or current operator policy), strict projection cardinality, writer map binding/authorization, frozen v3 request and integrity/revision checks before send and every retry, partial/indeterminate reporting, idempotent Nexum checkpoint and ownership/manual-content protection. Do not silently treat a committed partial result as full convergence; a later normal slot may fetch a genuinely new source snapshot. Status/preview remain local-only. Scheduled data sync **never** calls `wormholesystems_reconcile_linked_notes`, PATCHes notes, or activates the legacy selected-map note writer.
- Expose sanitized scheduler state in WHS status/config (enabled/blocked, configured map, cadence, next opportunity, last attempted/completed slot, last outcome, skip/failure reason, and coordination mode/health); distinguish disabled, unbound, busy, rate-limited, partial, indeterminate and complete. Emit bounded structured logs/metrics for slot start/skip, source/PUT outcome and duration without credentials, raw source payloads, private notes or frozen request bodies. Status reflects durable last sync-run evidence where available; process-local timer metadata is not a cross-replica success claim.
- Deterministic fake-clock/fake-transport tests: five-minute boundaries, initial delay, shutdown/restart with missed slots, >5-minute work, manual/scheduled collision, reconfigure/disable/remove and stale queued invocation, invalid policy/binding, no overlap/catch-up, 429/503 Retry-After, auth/fetch/projection failures, indeterminate PUT and frozen replay, local lifecycle and redacted status/logs. For this single-worker release test manual/scheduled contention through `syncMap` and assert the documented one-active-scheduler deployment gate; future scale-out must add cross-replica contention/loss/fencing tests before enabling another worker. Fixture-only tests: no live source/Nexum calls. `npm run build`, `npx vitest run`, and `git diff --check` must pass before rollout.
- Operator rollout: verify deployed v3 source/schema, Nexum v3 endpoint, actual bound map-scoped `wormholesystems_sync` key, persistent policy/source state, source rate limits (up to 100 serial detail GETs spaced one second, i.e. a run can outlast five minutes), **the verified one-active-`galaxy-0` StatefulSet configuration**, and logs/health before enabling. Recheck replica count and rollout overlap after any infrastructure change; >1 active scheduler is blocked pending shared coordination and fencing. Estimate GET volume against the real upstream quota; if five-minute polling violates it, stop activation and obtain an operator decision rather than increasing rate or bypassing Retry-After. Enable via existing explicit source test, writer bind and sync enable; no manual sync invocation is required. Confirm a full eligible scheduled write and later repeat via safe status/target evidence; do not perform live sync as part of contract/test work. Roll back by disabling source sync or deploying a prior revision, without deleting checkpoints/credentials.

## Expected implementation surface and out of scope

Likely `src/wormholesystems.ts`, `src/http.ts` (or shared service lifecycle), a focused scheduler/coordination component, status/tool exposure, unit tests and operator docs. No source API mutations, automatic linked-note writes, signature-name redesign, Nexum v4 endpoint, generic webhook/subscription engine, or inferred topology. The supported first release is **single active Galaxy worker** on the inspected StatefulSet/PVC; scale-out requires shared leader election/lease and verified fencing before a second scheduler is allowed; do not claim multi-replica safety from process-local locks.
