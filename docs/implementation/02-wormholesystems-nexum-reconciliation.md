# WormholeSystems source reconciliation

## Intended behavior

Extend the existing on-demand WormholeSystems source path for exactly its configured canonical Galaxy map and selected Nexum map. Keep Nexum's cache, existing API client, per-map decision boundary, and note PATCH path. Do not add polling/webhooks, a second approval service, generic approval/audit workflows, an outbox, or broad provenance machinery for topology/notes. The narrowly scoped durable standalone-signature binding/attempt journal in [04-wormholesystems-standalone-signature-sync.md](04-wormholesystems-standalone-signature-sync.md) is a separate dependency for that unit's cross-service writes, not a change to this unit's settled note behavior.

The dedicated Nexum key scope is `wormholesystems_sync`; it inherits read, events, and content-write capabilities and is bound to one target map. Its topology endpoint accepts only validated source IDs/EVE IDs, positions, and supported connection attributes. Nexum creates ownership records only for rows it creates; it never adopts matching manual topology. It updates or deletes only unchanged rows with those ownership records, preserves manual/unmatched rows and custom labels, and refuses deletes that would remove associated user data. The API capability is not a source-authority assertion.

For the selected source map, alliance note text is `.FROM-TO SIG DEST-CLASS SIZE [NOTES]`; reverse direction uses `..`, home is alias `0`, and branches use decimal aliases. Render only validated aliases/IDs and explicit alliance status annotations; do not infer signature identity, destination class, size, status, or annotation. Other maps keep the legacy chain-note behavior. While WormholeSystems source sync is enabled, the selected map's legacy note writer is suppressed, so missing/unknown source data never falls back to B/B notes.

## Current implementation and safety gate

- Source fetch, schema validation, snapshot persistence, cache-only preview, and the API capability exist. Preview is local-only and never mutates Nexum.
- The source adapter now derives topology evidence from a complete fetched map/member snapshot: opaque member IDs map to canonical EVE IDs, source positions are used as canvas coordinates, and source connection `type`/`ship_size` are accepted only when they match Nexum's supported enums. Source system status is visual intel, not topology liveness; expired mass/lifetime annotations do not remove a connection present in the complete list. The operator-approved initial 60,000 ms runtime policy in [03-wormholesystems-runtime-freshness-policy.md](03-wormholesystems-runtime-freshness-policy.md) replaces the env-only bound for the completed snapshot and required Nexum map/signature cache evidence; row timestamps are not required.
- Alliance-note evidence validates decimal aliases against `home_solarsystem_id`, directional source signature linkage, the configured annotation vocabulary, and destination class from canonical SDE data. Missing or ambiguous direction evidence blocks only that note. Unsupported connection values block topology apply without inventing defaults. Actual alliance deployment schema/auth/rate behavior remains unverified; no live source or Nexum requests were made.
- Per 03, report source-snapshot eligibility separately from **full** matching eligibility, which also requires fresh, healthy Nexum map/signature evidence and exact identity; invalid persisted policy cannot be displayed as the approved default. Preserve local-only unmatched diagnostics for every validated source signature without a connection reference, including assigned scan codes, even when a map has zero connections. Report only bounded source signature ID, scanner EVE system ID, available code and the missing-reference reason for this **linked-direction** diagnostic; these rows cannot establish an endpoint, linked-direction identity match, bookmark or writable note. A source signature with no referenced source edge never authorizes topology mutation or Nexum note PATCH. It may separately be a scanner-system standalone scan candidate under unit 04's independently blocked/guarded ownership contract.
- No live source or Nexum requests were made. No source polling or webhooks are introduced.
- Nexum signature PATCH remains unconditional. Use the existing per-map serialized Galaxy write path and extend its note-write behavior: on the selected source map, PATCH only exact source-to-target directional matches when Galaxy's pre-write observation finds the note empty or already equal to the desired alliance note; skip observed nonempty manual/unknown notes. Alliance source-map naming replaces legacy B/B.1 notes there, with no legacy fallback; other maps retain their legacy note behavior. This check is not atomic with independent Nexum UI/client edits: a manual edit between observation and PATCH can still be overwritten, as with the existing writer. Do not introduce an approval or CAS subsystem or promise full manual-edit protection. Topology API failure does not suppress independently eligible alliance-note PATCHes.
