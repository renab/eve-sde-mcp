# Galaxy → Nexum: authority-aware bookmark reconciliation

## Objective

Render verified WormholeSystems bookmark authority into the **selected** Nexum map's directional signature notes, replacing obsolete B/B.1-derived note writes there while preserving Nexum's independent live cache and every other map's existing behavior.

## Authority and dependencies

- [01-wormholesystems-source-and-sync.md](01-wormholesystems-source-and-sync.md) supplies a validated, fresh, map-scoped canonical source snapshot. Do not enable Nexum writes until its unresolved upstream authority and bookmark payload/specification are confirmed.
- `src/nexum-chain.ts` is the pure *legacy* identifier/note planner; `src/nexum.ts` `scheduleChain`/`reconcileChain` and `chainNoteFormat` currently schedule and write legacy notes, defaulting to `{chain}`. `src/tools/nexum.ts` exposes diagnostics and manual reconciliation. `src/nexum-store.ts` persists map-isolated resources/reservations. `docs/nexum.md` establishes that API-key signature-note PATCH exists but API-key `customLabels`/system changes and `bookmarkFormat` changes do not.
- The current WormholeSystems authority records were not available for inspection; exact canonical bookmark syntax, source field meanings and precedence over previous ledger `nexum/chain_note_format` records must be confirmed, not fabricated. The selected-map integration must not fall back to old B/B.1 note writes on source failure or missing authority.

## Scope and ordering

1. **Guard legacy writes first.** Introduce a persistent, map-scoped authority mode (`legacy` by default for untouched maps; `wormholesystems` only after explicit targeting). Every path to `scheduleChain`, `reconcileChain`, manual `nexum_reconcile_chain_notes`, and any deferred/in-flight legacy writes must check the mode at execution and immediately before each PATCH. Switching modes cancels/quiesces queued legacy reconciliation for that map before new sync may plan writes. Existing legacy reservation data/diagnostics may remain visible as historical, but cannot become the authority for notes in the target map. Changes to the old `chain_note_format` record must not re-enable legacy writes there. Never globally disable other maps.
2. Build a **pure matching/planning module** consuming one eligible source snapshot, one coherent Nexum cached map state plus signatures/resource timestamps, and the confirmed bookmark rule. Output deterministic proposed changes and categorized skip/conflict diagnostics; no HTTP or DB mutations in this module. Build the bookmark renderer separately from upstream normalization and matching. Verify required tokens, escaping/length limits and exact expected outputs against authoritative fixtures; unknown or unsupported formats make the entire source plan non-writable rather than generating `{chain}` or invented text.
3. Reconcile using the existing Nexum signature-note PATCH endpoint and healthy authorized map-access writer selection. Only changed notes that passed exact matching and ownership checks may be PATCHed; never PATCH Nexum system labels, connections, signatures' identity, or map metadata. Preserve existing optimistic cache update after success and idempotence on echoed `sig.changed` events. Expose a read-only dry-run preview and an explicit target-map apply operation (or make on-demand sync's apply flag explicit and default false); responses must list matched/proposed/skipped/conflicting counts and sanitized per-item reasons. No automatic application from incidental Nexum events until the authority and rollout policy have been confirmed.
4. Persist note-write provenance per canonical map + Nexum system ID + signature row ID: source identity/revision/digest, source connection and direction, Nexum connection ID and endpoints, rendered note hash/value (safe text only), prior note hash/value if needed for review, successful PATCH timestamp, and last observed Nexum resource freshness. Keep secrets out. An additive migration must not alter existing reservation assignments or ledger history. Record failures separately from successes. Recheck source revision, mode, map identity, Nexum signature/content and connection state before each write to prevent racing source refreshes/Nexum event updates. If any recheck fails, skip and require a fresh preview/reconciliation.

## Interfaces and matching invariants

Use the **canonical map ID**, never map name, to bind configuration, source snapshot, diagnostics, provenance and apply. A match requires: same EVE solar-system ID on each resolved endpoint (not names/classes), the full scanner-side directional signature identity (including code and relevant stable row ID where available), exact source↔Nexum connection identity established from both endpoints and directional signature references, current compatible connection state (not broken/expired), and freshness of **both** source observation and Nexum map/signature cache. Do not match via `whLeadsTo` name, class, partial signature code, stale provisional reservation, or arbitrary first candidate. If the upstream cannot establish identity for a still-unmapped connection, leave it unmatched; never mutate topology to manufacture a match. Require one-to-one correspondence in both directions where data exists; multiple candidates, reused codes, mismatched reverse references, unknown connection state, conflicting endpoint IDs, missing timestamps and stale snapshots are explicit skips. A safely known single direction can be planned only if confirmed upstream authority permits directional-only entries; otherwise skip it. Preserve Nexum map isolation even when two maps contain the same EVE systems/signatures.

Bookmarked note output is derived **only** from confirmed WormholeSystems authority and verified directional data; do not splice a legacy `{chain}` result into it. If upstream bookmark data conflicts with newer verified authority or has unresolved supersession, suppress writes and surface a blocker. Present the exact planned string and its source revision in preview so an operator can check it before apply. The UI's **Signature bookmark** format must be `{notes}` to copy note text verbatim; Galaxy cannot set that UI preference over Nexum's key API. Report it as a deployment prerequisite, not a silently applied setting.

Ownership: do not overwrite a manually edited Nexum note or an unrelated existing note. An initial replacement of pre-existing B/B.1 notes requires explicit operator confirmation of target map and approved replacement scope based on preview; prove which notes are legacy-managed via existing plan/current note comparison or recorded provenance. If ownership cannot be proven, skip and report manual review. On later syncs only update a row if its current note still equals the last successfully written managed note (or is an explicitly authorized initial legacy replacement). Never clear notes simply because a WormholeSystems record disappears, becomes stale or a link breaks. A successful unchanged application makes zero PATCHes.

Failures: read/snapshot/validation/stale/conflict conditions cause **no** writes, retain old Nexum notes and last good source snapshot with visible stale/ineligible status. Per-note Nexum 401/403 marks writer unavailable for writes without stopping map reads/events; 429/transient failures respect retry limits and `Retry-After`, retain uncommitted notes for a future explicit attempt, and never mark failed writes as completed. Partial success is reported per item and safe to retry because provenance and cached notes reflect only successful PATCHes. Preview has zero upstream calls. No source records, inference, or cached stale values may be represented as confirmed fresh Nexum state.

## Expected implementation surface

Extend `src/nexum.ts` scheduling guards and writer selection; add pure matcher/renderer beside `src/nexum-chain.ts` without repurposing that legacy planner; extend `src/nexum-store.ts` for mode and provenance; add authenticated MCP controls in `src/tools/nexum.ts` (and secret redaction for any new credential operation); update `docs/nexum.md` with the new mode/limitations. Keep transport GET for WormholeSystems and existing Nexum PATCH-only note scope separated.

## Validation

Tests in `tests/unit/nexum-chain.test.ts` (legacy regression), new fixture-based matcher/renderer tests, `tests/unit/nexum.test.ts` (scheduling/mode/restart/provenance), and `tests/nexum-http.test.ts` (MCP authorization/redaction and mock transport): exact rendered strings from approved authority fixtures; paired directions; concurrent same-code links; wrong EVE ID, mismatched reverse link, missing/stale resources, broken/expired edges, provisional/unmapped connections; old mode pending timer and echoed events cannot write B/B.1 on selected map; other map legacy behavior unchanged; manual note edits preserved; unknown ownership skip; no-op replay; partial failures, 401/403, 429 Retry-After; revision race and map isolation. Confirm zero upstream calls for preview, zero topology/custom-label/bookmark-format writes, no live credentials, `npm run build`, and `npx vitest run`.

## Out of scope

Rewriting the legacy chain planner, Nexum topology or system-label writes, browser-session impersonation, continuous polling/webhooks, changing ESI/ledger provenance, automatic destructive note cleanup.
