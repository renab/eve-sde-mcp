# WormholeSystems source reconciliation

## Intended behavior

Extend the selected-map WormholeSystems source path for exactly its configured canonical Galaxy map and selected Nexum map. Keep Nexum's cache, existing API client, per-map decision boundary, and note PATCH path. Unit 06 adds only the selected-map five-minute data-sync scheduler; do not add webhook listeners, a second approval service, generic approval/audit workflows, an outbox, or broad provenance machinery for topology/notes. [04-wormholesystems-topology-and-signatures-apply.md](04-wormholesystems-topology-and-signatures-apply.md) governs system/signature/link creation together in the existing transactional Nexum topology PUT, plus its source ownership/checkpoint and retry outcome; it does not change this unit's settled linked-note behavior. The former standalone POST/journal design is superseded.

The dedicated Nexum key scope is `wormholesystems_sync`; it inherits read, events, and content-write capabilities and is bound to one target map. The user's screenshot labeled `WormholeSystems sync (read + events + content + selected-map topology)` and explicit confirmation establish that the enrolled intended credential was created for that scope; `nexum_list_credentials` exposes safe observed read/event capabilities, not exact issued-key scopes. This confirmation does not bypass the topology endpoint's existing selected-map authorization: it still validates the request's selected credential, target map and source IDs/EVE IDs, positions, and supported connection attributes. A wrong selected key or API denial must be sanitized and reported, not blindly retried with alternate credentials. Nexum creates ownership records only for rows it creates; it never adopts matching manual topology. It updates or deletes only unchanged rows with those ownership records, preserves manual/unmatched rows and custom labels, and refuses deletes that would remove associated user data. The API capability is not a source-authority assertion; unit 04 extends **this same map-bound transaction** to signatures, with the same endpoint authorization and a signature-inclusive checkpoint rather than a separate generic content-write API.

For the selected source map, alliance note text is `.FROM-TO SIG DEST-CLASS SIZE [NOTES]`; reverse direction uses `..`, home is alias `0`, and branches use decimal aliases. Render only validated aliases/IDs and explicit alliance status annotations; do not infer signature identity, destination class, size, status, or annotation. Other maps keep the legacy chain-note behavior. While WormholeSystems source sync is enabled, the selected map's legacy note writer is suppressed, so missing/unknown source data never falls back to B/B notes.

## Current implementation and safety gate

- Source fetch, schema validation, snapshot persistence, cache-only preview, and the existing systems/connections topology PUT capability exist. In the current diagnostic implementation, `wormholesystems_sync_map` performs source GETs and stores a complete validated snapshot only; preview is local-only and never mutates Nexum. Topology/signature apply remains unavailable; unit 04 must add explicit data apply and extend the existing endpoint to signature rows. Linked-note reconciliation is a separate explicit tool, `wormholesystems_reconcile_linked_notes`, not part of sync or preview.
- The source adapter now derives topology evidence from a complete fetched map/member snapshot: opaque member IDs map to canonical EVE IDs, source positions are used as canvas coordinates, and source connection `type`/`ship_size` are accepted only when they match Nexum's supported enums. Source system status is visual intel, not topology liveness; expired mass/lifetime annotations do not remove a connection present in the complete list. The operator-approved initial 60,000 ms runtime policy in [03-wormholesystems-runtime-freshness-policy.md](03-wormholesystems-runtime-freshness-policy.md) replaces the env-only bound for the completed snapshot and required Nexum map/signature cache evidence; row timestamps are not required.
- Alliance-note evidence validates decimal aliases against `home_solarsystem_id`, directional source signature linkage, the configured annotation vocabulary, and destination class from canonical SDE data. Missing or ambiguous direction evidence blocks only that note. Unsupported connection types block data apply rather than inventing links; unit 04 defines explicit nullable size/default semantics for the existing PUT without claiming an unknown source size was large. Actual alliance deployment schema/auth/rate behavior remains unverified; no live source or Nexum requests were made.
- Per 03, report source-snapshot eligibility separately from **full** matching eligibility, which also requires fresh, healthy Nexum map/signature evidence and exact identity; invalid persisted policy cannot be displayed as the approved default. Preserve local-only unmatched diagnostics for every validated source signature without a connection reference, including assigned scan codes, even when a map has zero connections. Report only bounded source signature ID, scanner EVE system ID, available code and the missing-reference reason for this **linked-direction** diagnostic; these rows cannot establish an endpoint, linked-direction identity match, bookmark or writable note. A source signature with no referenced source edge never authorizes a **link** or Nexum note PATCH; its independently validated scanner-system row is a legitimate unit 04 signature write item even with zero connections. Unit 04 may also create a missing validated system. Missing target cache/system evidence cannot block those creations, but remains necessary for note matches.
- No live source or Nexum requests were made. This historical unit did not introduce source polling or webhooks; unit 06 supersedes that polling restriction for selected-map data sync.
- Nexum signature PATCH remains unconditional. Use the existing per-map serialized Galaxy write path and extend its note-write behavior: on the selected source map, PATCH only exact source-to-target directional matches when Galaxy's pre-write observation finds the note empty or already equal to the desired alliance note; skip observed nonempty manual/unknown notes. Alliance source-map naming replaces legacy B/B.1 notes there, with no legacy fallback; other maps retain their legacy note behavior. This check is not atomic with independent Nexum UI/client edits: a manual edit between observation and PATCH can still be overwritten, as with the existing writer. Do not introduce an approval or CAS subsystem or promise full manual-edit protection. Topology API failure does not suppress independently eligible alliance-note PATCHes.
