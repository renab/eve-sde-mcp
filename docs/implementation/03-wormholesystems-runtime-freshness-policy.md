# WormholeSystems runtime freshness policy

## Objective

Replace the env-only `GALAXY_WORMSYSTEMS_MAX_STALENESS_MS` matching limit with an operator-configurable, restart-persistent runtime policy. The operator-approved initial maximum age is **60,000 ms**. This policy limits a complete validated WormholeSystems source snapshot for data apply and note matching, and additionally limits required Nexum map/signature cache evidence for **note matching**. Missing target rows/cache must not prevent unit 04 from creating validated source-owned systems and signatures. The policy alone does not activate source sync or Nexum writes. Unit 06 schedules the existing validated selected-map sync every five minutes once separately enabled and validly writer-bound; the 60,000 ms snapshot-age gate remains a per-send limit, not the polling period.

## Authority and dependencies

- [02-wormholesystems-nexum-reconciliation.md](02-wormholesystems-nexum-reconciliation.md) governs map identity, fail-closed freshness, authority/ownership checks, and the per-map decision/write boundary. This contract resolves **only** its formerly unapproved numeric freshness bound and its env-only configuration mechanism; all settled note gates remain; transactional system/signature/link apply has distinct gates under [04-wormholesystems-topology-and-signatures-apply.md](04-wormholesystems-topology-and-signatures-apply.md).
- `src/wormholesystems.ts` currently reads `GALAXY_WORMSYSTEMS_MAX_STALENESS_MS`, stores the configured source in the `wormholesystems_config` singleton JSON row, and checks snapshot/cache freshness in status and preview. `src/tools/wormholesystems.ts` exposes the Cloudflare Access-protected operator MCP path. `tests/unit/wormholesystems.test.ts` contains its service and tool fixtures.
- One source configuration targets one canonical Nexum map. The freshness policy is **one global singleton setting**, not a per-map or per-credential preference; only the configured map can acquire eligible source matches. Do not treat changing this setting as a source configuration/credential revision change.

## Scope

1. Persist an effective `max_staleness_ms` of 60,000 on a **one-time** fresh/legacy upgrade when no operator value has been saved; read it independently of the process environment thereafter. Use explicitly named policy value, origin and revision fields in the existing singleton configuration JSON and the existing config/saveConfig access pattern. Add a durable, independent policy-initialization marker (an additive local schema/state record surviving service restarts and source-configuration removal), written atomically with the first initialized policy. Only a database with no marker and no policy fields is eligible for one-time approved-default initialization; an existing configured legacy source retains its identity and snapshot. Once the marker exists, a missing/malformed/invalid policy field is corruption, **never** another initialization opportunity. A policy field already present without a marker must be validated and retained, not overwritten; contradictory or invalid preexisting state fails closed rather than resetting. An absent source configuration exposes the approved default without creating a partial source config row; the marker retains reset state so later configuration cannot resurrect a previous override. Preserve policy fields across source reconfiguration, credential changes and sync enable/disable; read the latest config **inside** the decision boundary before saving. When source configuration is removed, atomically reset the durable policy state to approved 60,000 ms, including a new revision, and report that reset. If no source is configured, an operator may configure it first and then set the policy; `get_config` still reports the effective default.
2. Add a runtime MCP operator tool `wormholesystems_set_max_staleness` accepting exactly `{ max_staleness_ms: number }` (positive safe integer in milliseconds). The service applies a validated value atomically to local persistence under `mapDecisionBoundary` for the currently configured canonical map and returns the effective policy without secrets. Reject malformed, fractional, zero, negative, unsafe/overflow, string or non-finite values; invalid requests never alter the saved value. No source API calls, Nexum calls or note writes from this tool. Keep it behind the existing operator MCP/Cloudflare Access boundary; do not introduce a separate application-auth scheme.
3. Make `wormholesystems_get_config`, map sync status, preview, and source-sync result expose the same current effective bound and policy origin (`operator` or `approved_default`), never describe an unset/invalid env var as a blocker. Clearly separate **stored snapshot validation/activation eligibility**, **source-snapshot freshness eligibility**, and **full matching eligibility**. The stored flag reflects validated fetch and non-policy invalidations; source-snapshot eligibility additionally requires the current valid policy and a complete, still-fresh fetched snapshot; full matching eligibility additionally requires healthy, complete, fresh Nexum map/signature cache evidence, compatible identity/edges and all applicable matching gates. Status and preview must not say `eligible_for_matching: true` merely because the source snapshot is fresh while required Nexum evidence is missing/stale; report source-only eligibility and full eligibility under distinct named fields, with per-layer blockers. Source snapshot fetch completion time (not optional per-row observation times) must be finite, non-future and no older than the bound for both note matching and unit 04 data apply; each required Nexum map/signature resource timestamp must additionally meet that bound for **note matching** at status/preview/final note apply. The inclusive boundary is `now - timestamp <= max_staleness_ms`; a future timestamp always fails. Retain all unrelated snapshot, mode, resource health, identity and write-activation blockers.
4. Remove env-only read/dependency and document that `GALAXY_WORMSYSTEMS_MAX_STALENESS_MS` no longer controls matching; a preexisting env value is **not** silently imported or given precedence over the approved default or a persisted operator value. Document how an operator explicitly sets an alternative value at runtime and how to inspect it. Do not retain a secret-bearing or configuration-file-only write path.

## Interfaces and correctness constraints

- Service configuration/status return `staleness_policy: { max_age_ms, origin, revision }` with the same value that the matcher uses; maintain existing safe public fields where practical and remove obsolete `configuration_key` pointing to the retired environment variable. For persisted policy corruption, return `staleness_policy: { max_age_ms: null, origin: "invalid", revision: null }` and a safe `invalid_persisted_policy` blocker (or an explicit safe failed response with that blocker), **not** the approved default, an operator origin, or an invented effective bound. Source-only and full eligibility must both be false; status/preview/sync must not report a successful match or write. An unconfigured, intact reset state may report the approved default but cannot match. The setter response includes the committed bound, origin and revision. A policy change neither mutates the source payload/revision nor flips the stored `eligible_for_matching` flag merely because the age limit changed: that flag represents successful validated fetch and non-policy invalidations (including fetch failure, disabled sync, credential/map/config change). A newly completed successful eligible sync stores this flag independently of policy; status and preview compute freshness afresh. Treat the old status `eligible_for_matching` as **full** matching eligibility; use `stored_snapshot_eligible_for_matching` and `source_snapshot_eligible_for_matching` for the separate layers. If required Nexum evidence is unavailable, full eligibility is false even when a source-only check passes.
- Existing `previewLocked` also requires source connection/signature/system per-row `observedAt`, `freshUntil` and an invented `active` state. These must **not** become additional mandatory freshness evidence under the runtime policy: per 02, a complete validated fetch suffices for retrieval freshness when per-row timestamps are absent, and source lifetime/status annotations are not an `active` flag. Remove these false freshness blockers while retaining independently established identity/edge and Nexum-health checks. Real upstream expiry evidence, when confirmed by authority, must not be misrepresented as a fresh/traversable edge; do not infer authority from a larger configured age.
- Upgrade of legacy snapshots whose stored eligibility was `0` because the env policy was missing/invalid leaves them ineligible until a **new successful source sync**. This is conservative because the stored flag does not record why it was cleared. A policy update never turns a fetch-failed/disabled/reconfigured snapshot into an eligible one. Existing validated snapshots with the flag set retain their non-policy validation evidence and have freshness re-evaluated at decision time.
- Choose **fail/no-commit**, not queue-and-wait, for setter boundary acquisition: if a map decision/PATCH holds the canonical-map boundary, reject with a safe retryable busy error and make **no** policy/marker/revision mutation. A success response is emitted only after the DB transaction commits; it reports `committed: true` plus the saved value/origin/revision. Validation, busy, DB-write and service-stop failures must not claim commit; return `committed: false` only when non-commit is known, otherwise return a safe indeterminate error requiring `get_config` to determine the saved revision before retry. Setter and source config changes serialize with snapshot staging, preview and future map apply through the same boundary; source reconfiguration must preserve the most recent policy instead of saving an earlier config copy. A status read unable to obtain a coherent decision must not report eligibility as true. Already issued PATCHes cannot be revoked; the setter cannot succeed mid-PATCH. Queued previews/plans read current persisted policy under the boundary; apply rechecks policy revision together with source revision, map identity, Nexum resources, ownership and current note before any PATCH. Persist a new policy revision on **every** successful setter invocation (including same value); previews intended for subsequent apply bind to it so change-away-and-back invalidates them. Do not hold a DB transaction across network I/O. Existing single-process-only locking limitation and settled unconditional-note-PATCH/manual-edit race disclosure remain unchanged; unit 04 data apply does not PATCH notes.
- Missing, corrupt or invalid persisted policy **after one-time initialization**, including an incomplete policy in a configured source with an existing marker, must fail closed for matching and writes with the safe visible blocker above; never silently fall back to a permissive bound. Do not silently repair corrupt policy through a setter: require explicit recovery of durable state before mutations resume. No source credential, token or secret value appears in setter/status/error responses.
- Require **additive, bounded local-only unmatched diagnostics** for every unconnected source signature in the complete validated snapshot, including ones with available assigned scan codes; do not require a source connection reference to include it. Emit one per distinct source signature row, capped by the validated snapshot size, with `source_signature_id`, `scanner_eve_system_id`, `signature_code` (when present), and reason `no_source_connection_reference`; if a smaller output cap is needed it must accommodate at least 12 entries and report total and omitted counts. Do not echo raw upstream records, notes, credentials or unvalidated data. These rows are strictly unmatched/non-authoritative **for linked-direction matching and writes**: do not infer endpoints, topology, destination/name, bookmark text, or Nexum note writes from them. Unit 04 governs importing every independently validated scan into its scanner system, creating missing systems in the same transaction, under source-ownership/idempotency and map-bound credential checks. These unconnected rows remain in this **note-unmatched** diagnostic even after data import. Unit 02's separate linked-direction identity and manual-note safeguards remain; do not introduce a new note CAS gate.

## Expected implementation surface

`src/wormholesystems.ts` (policy persistence, snapshot staging, status/preview checks), `src/tools/wormholesystems.ts` (validated operator tool), focused tests in `tests/unit/wormholesystems.test.ts`, and operator docs describing the runtime tool, default, persistence and retired env variable. Update 02 only where it still says the bound is unapproved or must be separately provided.

## Validation and acceptance

- Fixture tests: fresh database, one-time legacy upgrade with and without valid existing snapshots, configured source, service restart against the same database, reconfigure, credential/sync transitions and removal/reset; explicit operator value persists on restart and is not clobbered by unrelated config writes. After initialization, delete/corrupt/replace a policy field and restart: marker prevents re-defaulting, `max_age_ms` is null/invalid, both eligibility layers fail closed and no write occurs. Restart after removal/reset shows approved default and no restored override; valid preexisting operator value without marker is retained rather than overwritten. Invalid setter inputs and invalid stored values fail safely with no update; environment values (including invalid or very large values) do not affect the effective bound.
- Deterministic clock tests for source completion time and required Nexum map/signature resource timestamps at exactly 60,000 ms, 60,001 ms, future, missing and malformed; with a fresh source and stale/missing Nexum resource, source-only eligibility is true but full `eligible_for_matching` is false with a Nexum blocker. Lowering/raising the bound immediately changes decision-time status/preview eligibility without fetching or mutating an otherwise valid source snapshot. Expiry between preview and final apply blocks a write. Legacy stored `eligible_for_matching=0` remains blocked until a new sync; failed/disabled snapshots stay blocked.
- Deferred interleaving tests: while an active map PATCH holds the boundary, setter returns busy/no-commit with unchanged bound/revision; retry after completion commits once and returns the saved value/revision. Race setter against source reconfiguration, sync staging and simultaneous setter invocations: no lost updates, no false success, and each committed invocation increments revision even on same-value retry; failed DB transaction does not claim commit. Queued decisions use the new policy and stale previews cannot authorize writes, including after value is changed back. Tool tests confirm schema, safe response, no external calls, no Nexum writes, no credential echo. A zero-connection fixture with 12 validated source signatures (including the two assigned codes) reports all 12 in bounded unmatched linked-direction diagnostics, no linked match, inferred endpoint/link or note write; missing codes are not invented. Unit 04 separately permits creation of validated systems and all 12 signatures in one transactional apply without inventing links; this policy still gates its fresh source snapshot. Preserve existing unrelated-map behavior and build/test with `npm run build` and `npx vitest run` using only fixtures; do not contact live services.

## Out of scope

Bookmark rendering, implementing unit 04 topology mutation, live authority verification, deployment Access verification, production Nexum apply activation, per-map policy overrides and speculative upstream observation ages. **Principal Reviewer re-reviews the revised cross-contract freshness boundary before implementation.**
